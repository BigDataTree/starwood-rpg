# 《星森傳說》從零重製標準化開發 SOP v2.0

版本：2.0.0-draft｜2026-11-23（Asia/Taipei）  
狀態：流程草案，**不得視為已完成重製或已核准全部素材**  
適用範圍：世界觀與地圖、玩法、程式、角色/場景/怪物/道具美術、測試、GitHub 部署、離線單檔交付。

> 一句話原則：**先定世界與資料權威，再做完整小範圍可玩版，通過驗收才量產；所有修改經分支、測試與整合關卡進入正式版。**

## A. 開發基線與已知教訓

- 使用者要求：手機線上遊玩、電腦 ZIP、電腦離線單檔 HTML 三種交付管道；三者需來自**同一 commit 與同一版本號**。

## B. 開發架構：兩條線、單一來源、三種發行成品

1. **維護線**：舊版 `main` 保持可玩，僅做必要的 P0 修正；先打 `legacy-v1.1.11` 備份 tag（須核對對應 commit）。
2. **重製線**：另開長期 `rewrite/v2`（名稱只是提案），所有重製工作以短期 `feat/*`、`art/*`、`fix/*` 分支及 PR 合入，不直接互相覆蓋或跨批改檔。
3. **唯一權威**：世界拓撲、角色清冊、怪物、物品、任務資料及素材來源均採機器可讀 JSON + 人可閱讀的 Markdown。顯示畫面與遊戲運作同讀這些資料，不維護相互矛盾的第二份資料。
4. **開發時模組化、發行時自動打包**：原始碼按 engine/world/entities/combat/ui/save/audio 等模組維護；Web 版可按區域載入素材，離線 HTML 由同一版本的建置器自動內嵌程式與所需資產；ZIP 同一 release 產生。**禁止人工改發行成品、從發行 HTML 反向繼續開發、上線時依賴易碎字串替換補丁。**
5. **手機第一級支援**：鍵盤、滑鼠、觸控同一輸入介面；相機/HUD/互動距離與 safe-area 按裝置適配；離線 HTML 在不依賴外部網路與 CDN 的條件下可啟動。

建議目錄（可依實際框架調整）：
```text
/docs/                 # GDD、世界設定、美術規範、SOP、決策紀錄
/data/                 # characters.json, zones.json, portals.json, quests.json, items.json
/assets/source/        # 權威原檔（不破壞地保留）
/assets/approved/      # 已驗收正式素材
/assets/candidates/    # 候選圖，程式正式建置不可引用
/src/engine/           # 遊戲主迴圈、渲染、載入、碰撞、鏡頭
/src/game/             # NPC/戰鬥/成長/任務/互動/存檔
/src/ui/               # HUD、對話、選單、手機操作
/tests/                # 單元、資料契約、傳送門與 E2E、效能
/tools/                # 圖像批次 QA、manifest 檢查、版本化打包
/reports/              # 每批驗收與 release 報告
```

## C. 七階段 + Stage Gate（不可跳關）

| 階段 | 必做工作 | 交付物 | Gate／可以進下一階段的條件 |
|---|---|---|---|
| S0 盤點凍結 | 讀原始碼/素材/存檔、保留玩法，將所有已知問題按 P0/P1/P2 分類，權威衝突登記 | `LEGACY_BASELINE.md`、功能清冊、問題清冊、資產 Manifest、備份 tag | 能追溯舊版每項功能、資產來源、基準 commit；舊版不受重製影響 |
| S1 世界＋玩法 | 世界大地圖、九區位置/入口、傳送圖、道路/障礙、主線、核心循環、玩法規則與最小可玩範圍 | `WORLD_MAP`、`zones.json`、`portals.json`、`GDD.md` | 使用者核准大地圖；所有傳送邊雙向/單向關係、落點與可走區域一致 |
| S2 美術規格＋權威 | 核對 77 位身分、肖像、全身圖及 64px；定比例、色盤、像素網格、透明、動畫；怪物/地形/道具規格 | `characters.json`、美術規格、權威圖 hash、驗收室、候選/定案分層 | 所有關鍵身分 ID 對照核准；小樣本（主角、固定 NPC、移動 NPC、怪物各至少一例）完整通過視覺/技術檢查 |
| S3 引擎基礎 | 模組化程式、渲染/相機、碰撞、鍵鼠/觸控、資料載入、版本化存檔、CI、自動測試、三種打包 | 可啟動技術 Demo、測試腳本、建置工作流程 | 桌機/手機皆可載入；進出傳送門、存讀檔、透明圖渲染和打包能自動/人工驗證 |
| S4 最小完整可玩版 | 以一個主要區域及相鄰的最小測試區實作完整探索→互動→戰鬥→獎勵→任務→傳送→存檔流程 | 玩家可自行操作的 Vertical Slice、測試報告、操作影片/截圖與網址 | 玩家認可核心手感與美術品質；不存在 P0/P1；線上版+離線 HTML 均能在手機/桌機實際遊玩 |
| S5 批次擴充 | 以已通過的模板批次製作全部區域、角色、NPC、怪物、物品與任務，保持跨批資料鍵一致 | 各批候選/權威檔、實機 Demo、PR、逐批 QA 報告 | 每批 E1–E7 通過、遊戲內回歸測試通過才合併；未過者不覆蓋正式素材 |
| S6 整合 Beta | 全路線遍歷、劇情通關、UI/觸控/音效/效能/存檔/異常路徑、長時間測試及修補 | Beta 版本、缺陷清單、裝置矩陣、效能數據 | P0=0、P1=0；P2 有紀錄且接受；三種成品同版本、跨裝置實測完成 |
| S7 發布維護 | 標記正式版本、release notes、GitHub Pages 部署、離線單檔/ZIP、hash 與回退演練 | 正式 v2.0.0、手機網址、電腦 ZIP、電腦 HTML、變更與測試紀錄 | 使用者實際開啟三種交付物；可回退到上一個穩定版；存檔不被無意清除 |

每一 Gate 的結論只能是 **PASS／FAIL／BLOCKED／NOT TESTED**；未知不得寫「已通過」。美術定案、世界結構、最小可玩體驗、正式發行等關鍵 Gate 須使用者確認；其餘技術驗證可自動執行。

## D. 世界地圖與傳送門：先拓撲後繪圖

1. **概念**：確定九區在世界中的相對位置、地理阻隔與探索順序，先繪高階地圖再進行場景繪製。
2. **唯一資料**：每個 zone 定義 `zoneId`、地圖尺寸、坐標系、碰撞地形、入口/出口、建築、主要道路、NPC/怪物區。
3. **門資料**：每組傳送點定義 `portalId`、from-zone、from-position、to-zone、spawn-position、朝向、啟用條件與可否反向。
4. **不變條件**：目的地需在可行走位置；門到抵達點不可卡死或立即重觸發；同一張世界大地圖與遊戲場景不能出現邏輯矛盾。
5. **檢查**：自動列出孤立區、不可達區、未配對門、反向錯位、出生點碰撞；提供傳送門總覽 Demo 讓人點擊逐對查看。

**禁止：**先靠目測隨機放傳送門、之後才用故事設定合理化其地理矛盾。

## E. 素材流水線：先定身分，後做動畫

### 身分與版本
每位角色固定：`stableId`（不可改）、`displayNo`、`name`、`role`、`portraitSourceHash`、`frontSourceHash`、`walkSheetHash`、`approvalStatus`、`approvedAt`。原檔與候選檔分離；只有 `approved` 能進入正式遊戲。

1. 先核對 77 位完整清冊及外觀、角色名字與職責；肖像與全身像必須是同一人物。
2. 肖像以既定 256×256 規格檢驗，不許非等比變形、黑白邊、裁切五官或擅改既定造型。
3. 64×64 正面源圖逐位放大檢查手、腳、帽、輪廓及透明邊；保持**原始像素網格**，不得將小圖放大後冒稱原生 64px。
4. 05–46 固定 NPC：僅需一張正面站立 64×64；01–04 主角與 47–77 移動 NPC：四方向、每方向三影格。
5. 192×256 的行走 Sprite Sheet：3 欄×4 列、每格 64×64，方向由上到下 `down,left,right,up`，動作 `step_left,idle,step_right`，播放 `0→1→2→1`。動畫必須是真正改變手腳姿態，不能整張移動充數。
6. 不要直接量產 35 位完整行走角：先以主角 01、一位固定 NPC、一位移動 NPC 及一隻怪物做**母版測試**，通過才批次 5–10 位。
7. 每批 QA：像素尺寸、alpha、越界、影格相似度、腳底錨點、遮擋順序；白/黑/綠/藍底、原生與整數放大、遊戲內四方向、移動/停止幀、手機/電腦皆測。
8. 驗收室顯示：肖像＋正面＋四方向/每幀＋對照來源＋核准狀態；角色 ID 由 manifest 讀取，避免編號直接印在會被裁切的圖片上。

已定案素材修改需明確變更要求與新版本；不能默默替換。**視覺外觀合格 ≠ 程式中已正確掛載**，兩項須分開驗收。

## F. 程式與內容模組化

- **Engine**：Game Loop、渲染、攝影機、碰撞、區域切換、畫面尺寸與載入。
- **Input**：鍵盤、滑鼠、觸控共同轉為行走／互動／選單操作；手機虛擬按鍵與全螢幕 HUD。
- **Entity**：唯一實體 ID、角色/NPC/怪物資料鍵、方向、動作狀態、事件及互動距離。
- **Gameplay**：戰鬥、技能/裝備/道具、任務、經濟、成長、劇情旗標；規則與 UI 不硬綁。
- **UI**：名稱牌避讓、互動提示、對話肖像、選單層級、手機 safe-area；保護遊戲可視區。
- **Save**：`schemaVersion`、版本相容、寫入前校驗、匯出/匯入備份、舊存檔搬遷或明確不相容提示。
- **Assets**：使用 manifest 索引、lazy loading/快取、明確載入失敗畫面；不可悄悄退回錯誤舊圖而假裝正確。
- **Build**：開發來源唯一；自動生成 Pages 靜態網站、ZIP 與離線 HTML；三者寫入相同版本＋git SHA。

設計建議：在重製早期先做穩定 2D Canvas/像素渲染，不因選擇新遊戲框架就重寫所有玩法；框架選型須用移動、碰撞、切圖與手機載入小樣本比較再決定。大型資產以「區域載入、共用素材快取、離線包一次產出」處理，不強迫網站將所有圖片一開始就載入。

## G. 測試矩陣與品質門檻

### 必須自動化
- 靜態/建置：語法錯、未定義 ID、缺失資產、重複角色/區域/門鍵、候選素材誤入 release。
- 地圖：全部傳送配對、抵達安全、地圖邊界、碰撞與必經道路可達。
- 角色：77 位角色 ID 映射；固定 NPC 不誤用行走圖；35 個移動外觀都能找到合法影格；人物肖像／全身像／場景實體映射一致。
- 功能：新遊戲、繼續遊戲、操作、對話、戰鬥、任務、道具、場景切換、儲存和讀檔。
- 交付：線上、ZIP、HTML 的 `version` 和 `commit` 相同；離線 HTML 不因外部 CDN 或 fetch 缺失而空白。

### 必須實機驗收
| 裝置/環境 | 基本驗收 |
|---|---|
| Windows 桌面 Chrome/Edge | 鍵盤移動、全螢幕、交互、切換地圖、存讀檔 |
| Android Chrome | 觸控移動、長按、虛擬鍵、旋轉、safe-area、效能 |
| iPhone Safari | 螢幕高度變化、觸控操作、畫面縮放、繼續遊戲 |
| 電腦離線 HTML | 斷網開啟、進遊戲、切區、存讀檔 |
| 手機 Pages 真實網址 | 不是只確認 GitHub Actions success，必須能真正進遊戲並操作 |

### 建議性能預算（初始目標，測得後調整）
- 桌面穩定目標約 60 FPS；一般中階手機遊玩目標至少約 30 FPS，避免頻繁掉幀。記錄場景、裝置與採樣方式，不用單一測得數字代表所有手機。
- 載入、互動反應、掉幀、尖峰記憶體、離線檔案大小都保留數據趨勢；未測量前**不宣稱已最佳化**。
- 初始下載體積與區域載入以實測與三種發行目標調整；單檔 HTML 可較大，但必須在目標裝置實際可用。

### 問題分級
- **P0 阻斷**：不能進遊戲、黑/白畫面、存檔毀損、必經流程卡死、資料/角色嚴重錯置。
- **P1 重大**：無法完成重要互動/戰鬥/過圖、嚴重卡頓或操作困難、已定案美術大量錯誤。
- **P2 改善**：小型排版、局部美術、音效平衡、便利功能、非阻斷的體驗優化。
- **P3 擴充**：新的區域、職業、支線、玩法系統與非必要豪華內容。

**Beta/正式發布原則：P0=0、P1=0，P2 需清單化接受；P3 不阻擋發布。**

## H. 一個任務的固定 SOP（所有 AI 對話共用）

1. **讀基線**：讀本 SOP、最新狀態檔、權威 manifest、對應任務規格與當前 git commit。
2. **定義範圍**：只處理一個可驗收的變更，不重複實作、也不偷偷增加新需求。
3. **建立分支**：一批角色、一項功能或一個區域一個分支；不得在不同對話同時寫同檔。
4. **先做最小示範**：美術先交前後對照/驗收室；玩法先交可操作 HTML；取得必要核准。
5. **實作與自測**：跑自動檢查、截圖比較、至少一輪操作測試與相關回歸測試。
6. **提交 PR**：清楚列基準 SHA、修改範圍、來源 hash、測試 PASS/FAIL/NOT TESTED、未解問題、可用 Demo、回退方式。
7. **整合者驗收**：批次互不覆蓋；確認對其他區域、UI、角色與存檔無破壞，才合到重製主線。
8. **發布與回報**：只以正式發布產物稱「最新版」；更新檔案/版本清單與三種連結。

## I. 正式發版規範

- **版本號**：v2.0.0 為首次通過全量 Gate 的重製正式版；之後 `MAJOR.MINOR.PATCH`，重大不相容、功能更新、修 bug 分別增加。測試版本以 `-alpha.n`、`-beta.n`、`-rc.n` 命名；未發布的測試 Demo 不冒充正式版。
- **版本單一來源**：由 package 或 release manifest 及 git tag 產生；標題、遊戲內版本、下載檔名、ZIP/HTML metadata 必須一致。
- **必要三連結**：手機 Pages、電腦 ZIP、離線 HTML；全部對應同一 SHA。發版說明需註明「已測」與「尚未實測」，不可只以建置成功表示遊戲正常。
- **回退**：保留前一個正式標籤及打包產物；存檔升級前可以備份；遇 P0 可以回復，不刪舊存檔。
- **Release note**：更新範圍、使用者可見變更、修正缺陷、相容性、測試矩陣、已知剩餘問題。

### 不再重犯
- 不先生成大量美術，事後才核對角色編號和身份。
- 不先畫場景，事後才補世界地理及傳送連結。
- 不以補丁字串、重複大型 HTML 或手動複製作為長期合併方式。
- 不把「圖檔存在」「Action 成功」「提供連結」等同於「遊戲已可玩」。
- 不讓不同對話各自決定正式版本號或無協調地修改 `main`。
- 不以一次多做功能為成就；以**交付後不必返工、可驗收、可回退**為完成標準。
